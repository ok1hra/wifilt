local-trx setup

Config is only applied at startup, never live -- Save restarts local-trx itself, no manual step needed, but every field below is frozen at whatever the last restart actually used until that happens.

Mode

Configure: local-trx does not talk to wifilt at all -- no CAT/keying/audio/ICOM-LAN hardware is opened, so every field and Test button on this page is free to use. Default for an install nobody has set up yet. Run: the real, currently-serving state. Pick it, then Save -- local-trx restarts into it, opens the real hardware, and locks the rest of this page below so what you see always matches what is actually running, never a half-edited guess. Switch back to Configure (then Save) to unlock everything again for editing/testing.

Startup

Only takes effect when local-trx is started on its own, directly -- not when started via the shared start-wifilt.sh/.bat launcher next to the installed binaries, which opens both tabs itself and turns this off for that run so the wizard tab does not open twice. Off by default either way (a headless/CI run must not spawn a browser), and a Save-triggered restart never reopens tabs regardless -- only a genuinely fresh, standalone start does.

Identity & listen IP

local-trx pretends to be an ICOM LAN-networked radio (the way an IC-705 or IC-7300 looks over the network), so that wifilt connects to it exactly as it would to a real ICOM transceiver. Behind that fake front, local-trx drives whatever real rig you configure in Steps 1-3 below over CAT (hamlib) and a DTR/RTS serial adapter -- wifilt never knows the difference.

What you type into wifilt's Setup → ICOM-LAN field to point it at this fake radio.

These are the values wifilt's Setup → LOCAL-TRX checkbox prefills by default (CI-V A6, IP 127.0.0.1). Change them here only if you also update them in wifilt.

Step 1: Audio

"default" uses the system's default device (works across locales). The meter shows real captured audio level while the mic/RX test is on -- speak, or key up the radio's RX, to see it move.

Step 2: CAT (rig control)

Frequency and mode go through the TrxNet device picked below. The radio's mode arrives coarse (SSB / CW / FSK / DIGI) and DATA modes (USB-D) cannot be set over TrxNet -- set the radio's data input by hand. No meters, RIT or power over TrxNet.

Step 3: Keying (CW/FSK + PTT)

Over TrxNet the device keys CW/FSK at its own speed (the WPM below is not sent). PTT over TrxNet is a lease: local-trx renews it every 300 ms and the device drops it by itself 1.5 s after the last renewal, so a crash or a pulled cable cannot leave the radio transmitting. OI3 needs firmware 20261031 or newer for /s-ptt.

A second, independent serial adapter from the CAT port above (bod 6/7) -- one line keys CW/FSK, the other is PTT.

TrxNet device

Used by whatever Steps 2 and 3 send through TrxNet. local-trx joins the TrxNet network as its own node and talks to the one device picked here; audio still uses this PC's sound card (Step 1).

wifilt on this PC already holds 5683, so local-trx listens on 5684 and the device answers there -- that needs TrxNet 1.08 in the device's firmware. With 5683 any firmware works, but only when nothing else on this PC uses TrxNet. local-trx appears on the network as LTX.01.
